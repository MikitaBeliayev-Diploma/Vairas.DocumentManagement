# Document Management implementation amendments

The reviewed ten-table model in the separate Documentation repository remains the source baseline. Its PROPOSED status and earlier DM-OPEN decisions are not retroactively rewritten. This service implements the agreed increment and records the added contracts here.

## Persistence and lifecycle

- Initial EF migration installs the canonical DDL and deferred constraints, with transaction wrappers removed because EF owns the migration transaction. A subsequent metadata-only migration records the scalar EF model. Later additive migrations retain exact generation results and signed-copy download references. SQL remains authoritative for composite FKs, deferred checks and partial uniqueness; EF does not recreate their graph through navigation properties.
- Seven additive tables are `document_job`, `operation_outcome`, `rendered_artifact`, `publication_decision`, `download_grant`, `inbox_message`, `document_review`. These support durable work, exact replay, both output formats, owner decisions, authenticated file delivery, event deduplication and human review. They do not duplicate a learning-credit ledger. Operational JSON is limited to command outcomes and missing-check diagnostics; the frozen rendering input is a private SourceBasis file.
- Preserve one root revision/audit per logical command. Review uses an immutable review row plus the root's DocumentChanged audit; it does not invent a Prepared-to-Prepared child transition forbidden by the canonical SQL. Version lifecycle changes have their own child revision events. An event never substitutes for parent CAS.
- Receipt status, job status, historical evidence status, version state and current selection are independent. Generation completion does not publish. Ready publication first reserves an Indeterminate version; a dedicated worker obtains/retrieves the durable owner decision before local finalization.
- No ordinary DELETE or automatic historical cleanup is implemented. Private objects abandoned before a final local transaction may be orphaned; storage inventory/retention is an explicitly controlled operational procedure. Failed jobs and their scan receipts remain inspectable.

## HTTP surface

- Implement the five original operations and add template/version/file APIs, contracts and signed copies, document catalogue/detail/review/publish/select/clear/withdraw/history, and authenticated content delivery. The exported OpenAPI and HTTP examples describe the actual controllers.
- All mutations require nonempty UUID Idempotency-Key, including the original contract/journal generation routes. Query `schoolId` is mandatory where the original route lacks it. Modified aggregates require exact expected revisions; publication compares both parent and version.
- Creation returns 201 with Location; immutable command replay returns 200 with the original response. Generation and Ready publication return 202 with a resource Location. A replay of generation retains the original accepted response; GET job/document supplies current progress.
- Accepted async commands and successfully committed commands retain their response. Authorization/input failures and commands rolled back before commit leave no business effects or key reservation; they are evaluated again on retry. Terminal async rejection is read from the job/document, while the original accepted HTTP response remains stable. Signed-copy declaration timestamps accept ISO offsets and are normalized to UTC for PostgreSQL.
- `sourceSnapshotVersion` is exactly `evidence-{EvidenceSnapshotId}-{DependencyRevision}` from the owning Learning payload. The earlier `training-snapshot-7` was a synthetic proposal example, not a running owner version. No latest-snapshot fallback exists.
- PDF is the default download format, with `format=docx` available. The optional `versionId` chooses a document version or contract signed-copy registration; `historical=true` explicitly permits an authorized historical artifact. Administrators use that option to preview Prepared output. Plain current download never falls back to an old version.
- Download URLs lead to this service, require the same authenticated user and expire in 60 seconds. Current Ready content performs a new Learning decision on each request. Signed-copy links recheck current selection; cancelled contracts require explicit history. Blob keys, SourceBasis and raw credentials are never public response fields.
- Public writes accept human user tokens. No MCP/delegated write endpoint is exposed by this increment; the confirmation workflow is not bypassed through a workload token.

## Owner contracts and publication semantics

- School adds `POST /internal/v1/documents/authority` under `school.documents.read`. It checks fresh UM activity, current membership, exact enrollment ownership and, for teachers, the current global Teacher binding and enrollment-group assignment. Administrator, own student and assigned teacher remain separate flags.
- Scope-only authority permits an effective school member to resolve a local resource's enrollment; it grants no enrollment/file access. DM performs that membership check before opening a user-selected tenant scope, then checks exact enrollment authority before returning data or effects. Background reconciliation uses only trusted recovery catalogue identities.
- UM adds `GET /internal/v1/users/{userId}/document-profile` under `profiles.documents.read`, returning only UserId, FirstName, LastName and Revision. DM resolves StudentId to UserId through the existing profile-binding API first.
- Learning adds exact snapshot expansion, current dependency revision, durable decision creation and outcome lookup under `learning.documents.read` / `learning.documents.decide`. Payloads include only the requested enrollment's retained evidence items, version/source references, bounded confirmation sequence, theory confirmation as observed at preparation, assessment outcome/date, programme/checklist versions and immutable rule editions. Historical fields are independent of current eligibility.
- Learning's `document_release_decision` table is insert-only and tenant-isolated. Runtime grants are applied by its updated reliability-grants script; role provisioning remains external. A metadata-only migration updates the existing EF model snapshot after the SQL migration.
- Publication and CurrentUse decisions bind school/enrollment/snapshot/revision/version/actor/kind/purpose/artifact digest. A publication operation is recoverable by the same UUID after a lost reply. Current-use requests always use a fresh operation UUID; a cached historical acceptance cannot authorize a later download.
- Decisions are committed under the same Learning school advisory lock as dependency changes. No HTTP calls or rendering run while the DM write transaction is held. The guarantee is readiness at the owner decision instant. A later correction preserves the historical decision and invalidates current use. There is no distributed transaction, lease through client consumption, or ability to recall downloaded copies.
- Authentication adds `vairas-document-management` to user audiences and maps the four new owner scopes to their internal audiences. It does not ship workload secrets or permissive client registrations. Local provider allowlists must be provisioned explicitly.

## Transport and files

- Consume existing PracticalRecordConfirmed/Revised, TrainingEvidenceInvalidated and School enrollment lifecycle events. Payloads are hints; DM re-reads Learning's authoritative revision instead of reconstructing educational facts. Durable Inbox identity/fingerprint, checkpoint monotonicity, local invalidation, delayed-event current-use checks and polling recovery cover duplicates, reordering and loss.
- Logical AsyncAPI channel names are mapped to externally provisioned producer-family topics and Subject-filtered subscriptions, matching the existing Learning/School transport. Poison/conflicting messages are dead-lettered after safe diagnostics. This increment publishes no newly invented document notification event.
- DOCX input uses allowlisted body block content controls, structural validation and bounded ZIP expansion. Scalar text and repeated evidence rows are filled with Open XML SDK; PDF conversion uses an isolated LibreOffice process/profile. Macro/embedding/field-code/external relationship inputs are rejected. Every output includes a generation/template/evidence provenance note and a current-status reminder.
- Azure Blob is private and accessed through server adapters. Upload uses If-None-Match; accepted bytes are SHA-256 checked on retrieval. ClamAV INSTREAM accepts only its exact OK response as Clean. Unavailability never becomes Clean. Pending/rejected templates, output and signed copies cannot back domain artifacts.

The completion report is an internal manual-handoff artifact. The demo templates and synthetic checklist fixtures are not approved legal forms, signature validation, official Regitra export compatibility or production deployment evidence.
